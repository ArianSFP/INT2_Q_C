# Qwen 32-block result: protocol, accounting, and audit

Canonical evaluation date: 2026-08-31.

## Result in one sentence

On a frozen deterministic panel of 32 real BF16 blocks from
`Qwen/Qwen3-30B-A3B`, the unpreconditioned POLARIS-SC-v2 control failed the
quality gate, while the otherwise identical codec with deterministic
zero-side-bit RHT passed at `0.05289448474927123` energy-weighted relative MSE
and `2.14971923828125` emitted bits per weight.

The qualifier “32-block deterministic panel” is part of the result. Nothing
in this document turns it into a full-checkpoint or statistical population
claim.

## Declared gate

For a unit-variance Gaussian source under squared error, the rate-distortion
lower bound is

```text
D_G(R) = 2^(-2R).
```

At `R = 2.15 bpw`:

| Quantity | Value |
|---|---:|
| Gaussian lower limit | `0.050765774772264724` |
| Allowed multiplicative excess | `1.05` |
| Five-percent MSE ceiling | `0.053304063510877964` |

The real-weight metric is the energy-weighted relative MSE

```text
                  sum over blocks ||x_b - xhat_b||^2
D_checkpoint = ------------------------------------------------.
                         sum over blocks ||x_b||^2
```

This is not the unweighted mean of block-relative MSEs. The decoder uses the
FP16 scale bytes actually serialized in each reservoir directory, so the
reported result includes scale-rounding error. Source energies and squared
errors are accumulated in FP64.

The joint panel gate requires all of the following:

1. the emitted reservoir is no larger than `2.15 * source_values` bits;
2. all logical arithmetic payloads fit the fixed global reservoir;
3. energy-weighted relative MSE is at most the five-percent ceiling; and
4. every independently decoded block passes integrity checks.

## Codec held fixed between arms

Both arms use the same polar-lattice core and serialization parameters:

| Parameter | Value |
|---|---:|
| Block length | `262144` |
| Polar lattice levels | 6 |
| Lattice alphabet | 64 |
| Lattice spacing `eta` | 0.25 |
| Gaussian test-channel distortion | 0.05110 |
| SC decision | randomized |
| Reconstruction scale | one FP16 value per block |
| Payload coding | causal arithmetic code |
| Logical payload capacity | 563,464 bits/block, globally pooled |

Let `g = sqrt(||x||^2/N)` and `z = x/g`. The exact arm applies the polar core
directly to `z`. The RHT arm instead supplies

```text
y = H_N diag(s) z / sqrt(N),
```

where `H_N` is a Walsh-Hadamard matrix and `s` is a deterministic Rademacher
vector generated by SplitMix64 from the block's manifest-derived seed. Decode
applies

```text
xhat = g * diag(s) H_N yhat / sqrt(N).
```

The transform is orthonormal and therefore preserves energy and Euclidean
error. Its signs are regenerated from the canonical checkpoint identity;
there is no transmitted sign vector, learned transform, calibration set, or
per-block RHT mode bit. The model schema and seed convention are decoder
inputs, just as tensor shapes and block order are.

The RHT arm consumes 89,406 more logical payload bits yet fits the same fixed
physical reservoir. It reduces aggregate MSE by `0.01030425299`, a paired
relative reduction of `16.304523%`.

Nineteen individual blocks improve and thirteen regress. The small
regressions are expected when a near-Gaussian block is replaced by another
near-Gaussian realization; the aggregate gain comes from eliminating severe
heavy-tail failures.

## Bottleneck diagnosis

The exact codec does not fail because its average bitstream is too long. It
has more than four times the logical headroom of the RHT arm. It fails because
the Gaussian-designed test channel is applied directly to non-Gaussian,
heavy-tailed blocks.

| Diagnostic | Raw blocks | RHT blocks |
|---|---:|---:|
| Median Pearson kurtosis | 3.37547 | 3.00146 |
| Maximum Pearson kurtosis | 114.29177 | 3.01946 |
| Error/kurtosis correlation | 0.99521 | -0.12121 |

Selected failure cases:

| Block | Raw kurtosis | Exact MSE | RHT kurtosis | RHT MSE |
|---|---:|---:|---:|---:|
| `attention_o.l47.b31` | 114.292 | 0.19918145 | 2.99286 | 0.05284034 |
| `embedding.b0` | 31.311 | 0.09489737 | 3.00918 | 0.05290561 |
| `router.l0.b0` | 24.481 | 0.07827474 | 2.99597 | 0.05285112 |
| `router.l47.b0` | 15.434 | 0.05803173 | 3.01719 | 0.05283185 |

For `attention_o.l47.b31`, the largest 0.1% of weights contain 20.33% of the
block's energy and the maximum magnitude is 42.20 RMS. RHT spreads this energy
without changing total energy, bringing the marginal distribution close to
Gaussian before the fixed polar codec sees it.

The observed correlation describes these 32 points. It should not be read as
a population parameter or causal estimate by itself; the paired transform
ablation supplies the stronger mechanistic evidence.

## Exact serialized-rate accounting

The panel reservoir has a fixed physical payload, even though each arithmetic
message has a variable logical length:

| Component | Formula | Bits |
|---|---:|---:|
| Header | `96 bytes * 8` | 768 |
| Per-block directories | `32 * (u32 length + FP16 scale)` | 1,536 |
| Fixed physical payload | `32 * 563,464` | 18,030,848 |
| **Physical file** | sum above | **18,033,152** |

Dividing by `32 * 262,144` source values gives exactly
`2.14971923828125 bpw`. The strict integer gate is evaluated as

```text
physical_bits * 20 <= 43 * source_values.
```

The RHT logical stream occupies 18,006,314 payload bits; the remaining 24,534
physical payload bits are verified zero. The exact-v2 stream occupies
17,916,908 bits and leaves 113,940 zero bits. No entropy estimate is used for
the physical-rate headline.

## Integrity and implementation binding

The panel runner validates each source hash before and after encoding and
re-derives both seeds from the canonical identity. It then:

1. encodes each block and verifies the encoder's arithmetic round trip;
2. concatenates logical messages into the fixed reservoir;
3. independently parses the complete physical file and its zero suffix;
4. extracts each variable-length record;
5. launches a fresh decoder process for each record;
6. uses the raw serialized FP16 scale bytes for reconstruction;
7. applies inverse RHT where declared; and
8. accumulates source energy and final squared error in FP64.

All 32 blocks in both arms pass. Key pinned implementation hashes from the
canonical run are:

panel run did perform fresh-process decoding for every record.

## Runtime environment

The canonical runs used:

- NVIDIA GeForce RTX 5090;
- CuPy 14.2.0;
- four concurrent GPU encoder/decoder workers; and
- `/workspace/int2-cupy-venv/bin/python` on the RunPod host.

Wall time was approximately 940 seconds for exact v2 and 943 seconds for the
RHT arm. This Python implementation prioritizes auditable bit identity and
fail-closed validation. These timings are not production throughput results;
the serial arithmetic loop is an obvious target for compiled, file-backed
implementation.

## Claim boundary and next experiments

This experiment establishes a real-weight feasibility result for a broad
matrix-role coverage panel. It does not establish:

- full-checkpoint logical-rate fit or whole-model MSE;
- any design-based confidence interval over Qwen weights;
- end-to-end perplexity, zero-shot accuracy, or generation quality;
- inference compatibility or acceleration; or
- a general state-of-the-art ranking against unrelated quantizers.

The descriptive role-population expansion in the paired audit yields RHT MSE
`0.0528661243` and mean logical payload `562,734.4402` bits/block. Because the
panel is not a probability sample, those values must not be promoted to
checkpoint estimates.

The next defensible sequence is:

1. preregister a probability sample large enough for role-aware uncertainty,
   or encode all 116,470 rank-2 blocks;
2. emit and independently parse a complete checkpoint reservoir;
3. reconstruct every tensor, including explicitly budgeted rank-1 data;
4. run perplexity and downstream evaluations against the BF16 baseline; and
5. replace the reference arithmetic loop with a production implementation
   while retaining byte-for-byte conformance tests.

Until those tests are complete, the precise conclusion is: **RHT-completed
POLARIS-SC-v2 passed the declared rate/distortion gate on this frozen Qwen
32-block panel; exact unpreconditioned POLARIS-SC-v2 did not.**
